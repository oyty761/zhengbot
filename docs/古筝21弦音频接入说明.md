# 古筝 21 弦音频接入说明

## 资源存储方式

项目数据库不保存 MP3 二进制内容。`digital_asset` 表保存可访问地址、MIME 类型、SHA-256 和时长，文件本体由 Spring Boot 静态资源目录提供。

MP3 文件位置：

```text
backend/src/main/resources/static/assets/audio/guzheng/
```

运行后的访问地址格式：

```text
/assets/audio/guzheng/string_01_D6.mp3
```

原始采样压缩包和音频加工过程文件不属于运行资源，不应上传到仓库。

## 数据库关系

每根弦涉及以下数据：

1. `instrument_part`：琴弦部件，业务编码为 `STRING_01` 至 `STRING_21`。
2. `string_profile`：弦号、MIDI 音高和音区；现有种子数据已经完整。
3. `digital_asset`：每个 MP3 对应一条 `asset_kind='AUDIO'` 的资源记录。
4. `part_resource`：以 `resource_role='DEMO_AUDIO'` 把琴弦部件与对应 MP3 关联。

琴弦与文件按相同编号一一对应：

```text
STRING_01 -> string_01_D6.mp3
STRING_02 -> string_02_B5.mp3
...
STRING_21 -> string_21_D2.mp3
```

完整音名和频率见音频目录中的 `弦号与音频对应说明.md` 和 `strings.json`。

## 导入数据库

新建开发数据库时，按 `backend/README.md` 的顺序执行初始化脚本。`seed_data.sql` 已经包含全部 21 条音频资源和关联。

如果数据库已经存在，不要重新执行会清空演示数据的 `seed_data.sql`，只执行：

```text
backend/guzheng_string_audio_data.sql
```

增量脚本可重复执行。它只移除琴弦部件原有的 `DEMO_AUDIO` 关联，不删除旧 `digital_asset`，避免影响其他模块。

## 接口验收

后端启动后检查静态文件：

```text
GET http://localhost:8081/assets/audio/guzheng/string_01_D6.mp3
GET http://localhost:8081/assets/audio/guzheng/string_21_D2.mp3
```

再逐弦检查试听接口：

```text
GET http://localhost:8081/api/instrument-explore/structure/string-highlight?string_no=1&action=play
GET http://localhost:8081/api/instrument-explore/structure/string-highlight?string_no=21&action=play
```

1 号弦应返回：

```json
{
  "stringNo": 1,
  "highlight": null,
  "pitch": "D6",
  "region": "高音区",
  "audioUrl": "/assets/audio/guzheng/string_01_D6.mp3",
  "action": "play"
}
```

21 号弦应返回 `pitch: "D2"` 和 `audioUrl: "/assets/audio/guzheng/string_21_D2.mp3"`。

接口查询参数是 `string_no`，响应 DTO 字段是驼峰格式 `stringNo`、`audioUrl`。

## 仓库文件范围

需要提交：

- `backend/src/main/resources/static/assets/audio/guzheng/` 中的 21 个 MP3及说明文件
- `backend/seed_data.sql`
- `backend/guzheng_string_audio_data.sql`
- `backend/src/main/resources/application.yml`
- 两份同步的乐器探秘接口文档
- 本说明文件

不需要提交：原始下载压缩包、Ableton 工程、临时分析脚本、波形图和音频工具依赖。
